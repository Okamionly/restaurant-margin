## Bug fixé

**Fichier** : `api-lib/routes/referrals.ts`  
**Ligne** : 200 (avant fix)  
**Type** : Feature manquante — email de notification parrain non envoyé

### Contexte

Le webhook interne `POST /api/referrals/qualify` est appelé depuis le webhook Stripe
quand un filleul passe en Pro/Business. Il met à jour le statut Referral en `qualified`
mais ne notifiait pas le parrain, laissant la récompense (1 mois Pro gratuit) invisible
du côté utilisateur.

### Avant

```typescript
await prisma.referral.update({
  where: { id: referral.id },
  data: { status: 'qualified' },
});

// TODO : envoyer email au parrain "Votre filleul a souscrit, vous avez gagné 1 mois gratuit !"

res.json({ qualified: true, ... });
```

### Après

```typescript
await prisma.referral.update({
  where: { id: referral.id },
  data: { status: 'qualified' },
});

const resendKey = process.env.RESEND_API_KEY;
if (resendKey && referral.referrerId) {
  const referrer = await prisma.user.findUnique({
    where: { id: referral.referrerId },
    select: { email: true, name: true },
  });
  if (referrer?.email) {
    const resend = new Resend(resendKey);
    await resend.emails.send({
      from: 'RestauMargin <contact@restaumargin.fr>',
      to: referrer.email,
      subject: 'Bonne nouvelle ! Votre filleul a souscrit 🎉',
      html: `...`,
    }).catch((err: Error) => {
      console.error('[REFERRALS/qualify] email parrain failed:', err.message);
    });
  }
}
```

### Détails du fix

- Import `Resend` ajouté en tête du fichier (dépendance déjà présente : `resend@^6.9.4`)
- Fetch de l'email du parrain via `prisma.user.findUnique`
- Envoi conditionnel si `RESEND_API_KEY` présent (safe en dev sans la clé)
- Erreur d'envoi non-bloquante (`.catch`) — ne casse pas le webhook Stripe
- +22 lignes / +1 import
