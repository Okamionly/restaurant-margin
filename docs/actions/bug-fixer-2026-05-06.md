## Bug fixé

**Fichier** : `client/src/pages/RecipeDetail.tsx`  
**Lignes** : 344–345 (après ajout import à la ligne 6 et hook à la ligne 125)  
**Type** : i18n manquant — strings hardcodées en français pour tous les utilisateurs

### Contexte

`RecipeDetail.tsx` était la seule page principale à ne pas importer `useTranslation`. Les états loading et not-found étaient affichés en français quelle que soit la langue de l'utilisateur (EN/AR/ES/DE). Toutes les autres pages similaires (`Recipes.tsx`, `Ingredients.tsx`, `Suppliers.tsx`) utilisaient déjà `t()`.

### Avant

```tsx
// aucun import useTranslation
export default function RecipeDetail() {
  // aucun const { t } = useTranslation()
  ...
  if (loading) return <div ...>Chargement...</div>;
  if (!recipe) return <div ...>Recette non trouvée</div>;
```

### Après

```tsx
import { useTranslation } from '../hooks/useTranslation';

export default function RecipeDetail() {
  const { t } = useTranslation();
  ...
  if (loading) return <div ...>{t('common.loading')}</div>;
  if (!recipe) return <div ...>{t('common.notFound')}</div>;
```

### Locales modifiées

- `client/src/locales/fr.json` : ajout `"notFound": "Introuvable"` dans la section `common`
- `client/src/locales/en.json` : ajout `"notFound": "Not found"` dans la section `common`
- ar/es/de : non modifiés (section `common` absente, `common.loading` manquait déjà — problème pré-existant hors scope)

### Détails du fix

- +1 import `useTranslation`
- +1 ligne `const { t } = useTranslation()`
- 2 strings hardcodées remplacées par `t()`
- +1 clé `common.notFound` dans fr.json et en.json
- Total : +6 lignes / -2 lignes
