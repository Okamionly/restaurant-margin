## Bug choisi

**Fichier** : `client/src/pages/Settings.tsx`  
**Catégorie** : Bug logique / données jamais chargées  
**Sévérité** : Moyenne — UI affiche toujours 0/500 appels IA

### Description
L'onglet **Facturation → Utilisation** affichait systématiquement `0/500 appels IA` et `0% utilisé ce mois` car l'état `usageStats` n'était jamais hydraté depuis l'API. Le TODO `GET /api/usage/current` était présent depuis le FIX 2026-04-28 (retrait des fake data) mais jamais implémenté.

L'endpoint réel `GET /api/ai/usage` existait déjà dans `api-lib/routes/ai.ts` (ligne 1505) et renvoyait `{ used, limit, percentage, tokens, estimatedCost, month }`.

### Avant
```ts
// Billing — TODO: GET /api/billing/history + GET /api/usage/current
const [currentPlan] = useState<'pro' | 'business'>('pro');
const [usageStats, setUsageStats] = useState({ aiCalls: 0, aiLimit: 500, ... });

useEffect(() => {
  loadStats();
  loadReferrals();
  loadTeamMembers();
}, []);
```

### Après
```ts
// Billing — TODO: GET /api/billing/history
const currentPlan = (user?.plan === 'business' ? 'business' : 'pro') as 'pro' | 'business';
const [usageStats, setUsageStats] = useState({ aiCalls: 0, aiLimit: 500, ... });

useEffect(() => {
  loadStats();
  loadReferrals();
  loadTeamMembers();
  loadUsageStats();  // ← ajouté
}, []);

async function loadUsageStats() {
  try {
    const res = await fetch(`${API_BASE}/ai/usage`, { headers: authHeaders() });
    if (res.ok) {
      const data = await res.json();
      setUsageStats({ aiCalls: data.used || 0, aiLimit: data.limit || 500, storageUsed: 0, storageLimit: 5 });
    }
  } catch (err) { console.error(err); }
}
```

### Bonus
`currentPlan` était hardcodé `'pro'` via `useState`. Remplacé par une dérivation de `user?.plan` pour que le plan affiché corresponde au vrai plan de l'utilisateur.

### Impact
- L'onglet Utilisation affiche maintenant les vrais chiffres d'appels IA du mois courant
- La carte du plan actif (Pro/Business) est correctement surlignée selon le compte
