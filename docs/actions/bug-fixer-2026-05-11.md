## Bug choisi

**Fichier** : `client/src/pages/Dashboard.tsx`  
**Ligne** : 1400 (avant fix)  
**Catégorie** : Bug logique / graphique visuellement incorrect  
**Sévérité** : Moyenne — graphique "Distribution des marges" mal calibré

### Description

Le widget **Profitability → Distribution des marges** (graphique en barres à 5 colonnes) calculait `maxCount` de façon erronée à chaque itération du `.map()` :

```ts
// AVANT — bug
const maxCount = Math.max(...recipes.map(() => 1), recipes.length);
```

- `recipes.map(() => 1)` génère `[1, 1, ..., 1]` (n fois)
- `Math.max(1, 1, ..., 1, n)` = toujours `n` (= `recipes.length`)

**Conséquence** : les hauteurs de barres étaient calculées comme `(bucket.count / total_recipes) * 80` au lieu de `(bucket.count / max_bucket_count) * 80`. La barre la plus haute n'atteignait **jamais** 80px sauf si toutes les recettes tombaient dans un seul bucket.

**Exemple concret** : 10 recettes, 8 en marge > 80%. La barre verte aurait dû faire 80px (max), elle faisait 64px (8/10 × 80). Le graphique semblait "plat" sans raison.

### Avant

```tsx
{[
  { label: '< 50%', count: ..., color: '#dc2626' },
  ...
].map(bucket => {
  const maxCount = Math.max(...recipes.map(() => 1), recipes.length); // BUG
  const height = maxCount > 0 ? Math.max((bucket.count / maxCount) * 80, 4) : 4;
  return ( ... );
})}
```

### Après

```tsx
{(() => {
  const buckets = [
    { label: '< 50%', count: ..., color: '#dc2626' },
    ...
  ];
  const maxCount = Math.max(1, ...buckets.map(b => b.count)); // max réel des buckets
  return buckets.map(bucket => {
    const height = Math.max((bucket.count / maxCount) * 80, 4);
    return ( ... );
  });
})()}
```

### Impact
- La barre la plus haute atteint maintenant toujours 80px (max)
- Les autres barres sont correctement proportionnelles
- `Math.max(1, ...)` protège contre la division par zéro si tous les buckets sont vides
