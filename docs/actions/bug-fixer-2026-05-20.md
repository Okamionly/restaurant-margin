# Bug Fixer — 2026-05-20

## Bug fixé : `/api/health` retournait `services: null` pour les outils de monitoring

### Fichier
`api/index.ts`

### Diagnostic
Deux problèmes combinés :
1. **Route dupliquée** — une deuxième `app.get('/api/health')` existait ligne 529 (commentée `env: 'vercel'`) qui ne retournait aucun champ `services`.
2. **Gate admin-only** — la première route (ligne 424) renvoyait `{ status: 'ok' }` sans `services` pour les requêtes non-admin. Seul un JWT admin voyait le vrai diagnostic. Les outils de monitoring (Uptime Robot) n'ont pas de token → `services` absent/null.

### Avant
```typescript
// Non-admin → pas de services
if (!isAdmin) {
  return res.status(200).json({ status: 'ok' });
}
// Admin seulement : services: { database, api }

// + doublon ligne 529 :
app.get('/api/health', (_req, res) => {
  res.json({ status: 'ok', env: 'vercel' });
});
```

### Après
```typescript
app.get('/api/health', async (_req, res) => {
  // Ping DB Prisma
  let dbStatus = 'ok';
  try { await prisma.$queryRaw`SELECT 1`; } catch { dbStatus = 'error'; }
  // Vérif clé Anthropic
  const aiStatus = process.env.ANTHROPIC_API_KEY ? 'ok' : 'missing_key';
  res.status(healthy ? 200 : 503).json({
    status: healthy ? 'ok' : 'degraded',
    services: { database: dbStatus, ai: aiStatus, api: 'ok' },
    // + timestamp, uptime, responseTime
  });
});
// Doublon supprimé
```

### Impact
- Monitoring Uptime Robot / alerting maintenant fonctionnel
- 503 automatique si la DB tombe → alertes correctes
- Champ `ai: 'missing_key'` détecte une variable d'env manquante en prod

CTO audit 2026-05-16 — dette technique #2 : "services null empêche tout monitoring réel"
