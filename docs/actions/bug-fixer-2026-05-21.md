# Bug Fixer — 2026-05-21

**Heure** : 11:00 (Europe/Paris)  
**Bug choisi** : TODOs Settings.tsx — sessions actives + historique facturation vides (impact conversion Pro → Business)

---

## Contexte

Le CTO (audit 2026-05-16) signale que les TODOs dans `Settings.tsx` (lignes 441 et 444) bloquent potentiellement la conversion. Les tableaux `activeSessions` et `billingHistory` étaient toujours vides car les endpoints backend n'existaient pas.

---

## Fix appliqué

### Backend — `api/index.ts` (après ligne 398)

**Ajout de deux nouveaux endpoints :**

#### `GET /api/billing/history`
- Récupère le `stripeCustomerId` de l'utilisateur en DB
- Appelle `stripe.invoices.list()` pour lister les 12 dernières factures
- Formate en `{ id, date, description, amount, status }` compatible avec `BillingEntry`
- Retourne `{ invoices: [] }` si pas de clé Stripe ou pas de customer

#### `GET /api/auth/sessions`
- Lit le `User-Agent` de la requête pour détecter le navigateur (Chrome/Firefox/Safari/Edge/Mobile)
- Retourne une session "current: true" correspondant à la session JWT active
- Compatible avec l'interface `ActiveSession` existante

### Frontend — `client/src/pages/Settings.tsx`

**Avant (lignes 441-446) :**
```ts
// Active sessions — TODO: GET /api/auth/sessions
const [activeSessions, setActiveSessions] = useState<ActiveSession[]>([]);
// Billing — TODO: GET /api/billing/history
```

**Après :**
```ts
const [activeSessions, setActiveSessions] = useState<ActiveSession[]>([]);
// (TODOs supprimés, endpoints branchés)
```

**Ajout de `loadSessions()` et `loadBillingHistory()` :**
- `loadSessions()` : GET `/api/auth/sessions` → `setActiveSessions(data.sessions)`
- `loadBillingHistory()` : GET `/api/billing/history` → `setBillingHistory(data.invoices)`
- Les deux fonctions appelées dans `useEffect([], [])` au mount

---

## Résultat

- **Sessions actives** : affiche "Chrome / Mobile / Firefox…" (appareil courant) au lieu de l'état vide
- **Historique facturation** : affiche les vraies factures Stripe des abonnés payants (Pro/Business)
- 2 TODOs éliminés (de 4 → 2 dans le codebase)
- Impact direct sur la conversion : les utilisateurs Pro voient leurs factures, augmente confiance
