# Bug Fixer — 2026-05-22

**Heure** : 11:00 (Europe/Paris)  
**Bug choisi** : `session.lastActive` affiché brut ISO dans Settings.tsx (régresssion introduite le 21/05)

---

## Contexte

Le bug-fixer du 21/05 a branché `GET /api/auth/sessions` sur l'API réelle et injecté `lastActive: new Date().toISOString()` depuis le backend. Le frontend affichait cette valeur brute sans formatage :

```
Session active -- 2026-05-22T09:00:00.000Z
```

Au lieu d'un affichage lisible en français.

---

## Analyse

- **Fichier** : `client/src/pages/Settings.tsx`, ligne 1613 (après la PR du 21/05)
- **Root cause** : aucun formatage appliqué à `session.lastActive` lors de l'affichage
- **Impact** : UX dégradée sur la page Paramètres, onglet Sécurité — visible par tout utilisateur connecté

---

## Fix appliqué

### Ajout d'un helper `formatSessionDate` (avant le composant Settings)

```ts
function formatSessionDate(iso: string): string {
  const d = new Date(iso);
  if (isNaN(d.getTime())) return iso;
  const now = new Date();
  const time = d.toLocaleTimeString('fr-FR', { hour: '2-digit', minute: '2-digit' });
  if (now.toDateString() === d.toDateString()) return `Aujourd'hui à ${time}`;
  const yesterday = new Date(now);
  yesterday.setDate(now.getDate() - 1);
  if (yesterday.toDateString() === d.toDateString()) return `Hier à ${time}`;
  return d.toLocaleDateString('fr-FR', { day: '2-digit', month: '2-digit', year: 'numeric' }) + ` à ${time}`;
}
```

### Avant (ligne 1613) :
```tsx
<p className="text-xs ...">{session.location} -- {session.lastActive}</p>
```

### Après :
```tsx
<p className="text-xs ...">{session.location} · {formatSessionDate(session.lastActive)}</p>
```

- Remplace le `--` par le séparateur typographique `·`
- Affiche "Aujourd'hui à HH:MM" si la date est aujourd'hui
- Affiche "Hier à HH:MM" si la date est hier
- Sinon : "JJ/MM/AAAA à HH:MM"
- Guard `isNaN` pour les valeurs invalides (fallback au string brut)
