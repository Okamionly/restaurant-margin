### Après
```tsx
// Nouvelle fonction (ligne 855)
async function handleManageSubscription() {
  setPortalLoading(true);
  try {
    const res = await fetch(`${API_BASE}/stripe/portal`, { method: 'POST', headers: authHeaders() });
    if (!res.ok) throw new Error('Erreur serveur');
    const data = await res.json();
    if (data.url) window.open(data.url, '_blank');
    else throw new Error('URL manquante');
  } catch {
    showToast('Impossible d\'ouvrir le portail Stripe', 'error');
  } finally {
    setPortalLoading(false);
  }
}

// Bouton corrigé
<button
  onClick={handleManageSubscription}
  disabled={portalLoading}
  className="... disabled:opacity-60 disabled:cursor-not-allowed"
>
  {portalLoading ? 'Chargement...' : 'Gerer mon abonnement'}
</button>
```

### Raison
La route backend `POST /api/stripe/portal` existait et retournait une URL de portail Stripe valide, mais le bouton frontend ne l'appelait pas — il affichait seulement un toast sans redirection. Un utilisateur voulant gérer son abonnement (upgrade Pro → Business ou annuler) était bloqué silencieusement. Fix critique pour la conversion.

### Impact
- Débloque la gestion d'abonnement (upgrade, annulation, mise à jour CB)
- Loading state ajouté pour éviter les double-clics
- Error toast si la route échoue
