# Bug Fixer — 2026-05-26

## Bug fixé

**Fichier** : `client/src/hooks/useTranslation.ts`  
**Lignes** : 34-44 (fonction `t`)

### Symptôme
Les utilisateurs avec la langue réglée sur Arabe (AR), Espagnol (ES) ou Allemand (DE) voyaient les clés brutes (`login.title`, `login.emailPlaceholder`, `common.error`, etc.) au lieu du texte traduit sur la page de connexion — et potentiellement sur toute page utilisant une clé i18n absente de ces locales.

### Cause
Le commit `cc0e6a8` (2026-05-25) a ajouté 43 clés `login.*` et les clés `common.*` dans `fr.json` et `en.json` uniquement. Les locales AR/ES/DE n'ont que 7 sections sur 1367 — elles étaient déjà en retard mais le hook ne gérait aucun fallback. `getNestedValue` retourne le chemin de clé brut si absente, sans jamais consulter la locale FR.

### Avant
```ts
const t = useCallback(
  (key: string): string => {
    const dict = locales[locale] || locales.fr;
    return getNestedValue(dict as Record<string, unknown>, key);
    // ↑ retourne "login.title" si clé absente en AR — aucun fallback
  },
  [locale]
);
```

### Après
```ts
const t = useCallback(
  (key: string): string => {
    const dict = locales[locale] || locales.fr;
    const value = getNestedValue(dict as Record<string, unknown>, key);
    if (value === key && locale !== 'fr') {
      return getNestedValue(locales.fr as Record<string, unknown>, key);
    }
    return value;
  },
  [locale]
);
```

### Impact
- Toute clé manquante dans AR/ES/DE retombe sur le texte français au lieu de la clé brute
- Fix proactif : toutes les futures clés ajoutées uniquement en FR seront dégradées gracieusement
- 5 lignes modifiées, 0 dépendance ajoutée
