### Problème — Décalage de date timezone (UTC vs heure locale)

`new Date("YYYY-MM-DD")` en JavaScript interprète une chaîne ISO date-seule comme **UTC midnight**.  
Pour un utilisateur en France (UTC+2), `new Date("2026-06-05")` produit `2026-06-04T22:00:00` heure locale.  
`setHours(0, 0, 0, 0)` ramenait ensuite la date au **4 juin local**, soit un jour avant la vraie DLC.

Conséquences :
- Un produit avec DLC "05 juin" apparaissait **expiré le 4 juin** (un jour trop tôt).
- La date affichée dans la liste était **"04 juin"** au lieu de **"05 juin"**.

### Avant
```typescript
function getDaysLeft(dlc: string): number {
  const today = new Date();
  today.setHours(0, 0, 0, 0);
  const expiry = new Date(dlc);          // UTC midnight → décalé
  expiry.setHours(0, 0, 0, 0);
  return Math.ceil((expiry.getTime() - today.getTime()) / 86400000);
}

// affichage
new Date(p.dlc).toLocaleDateString(...)   // même bug
```

### Après
```typescript
function parseDlcDate(dlc: string): Date {
  // Parsing manuel en heure locale pour éviter le décalage UTC
  const [y, m, d] = dlc.split('-').map(Number);
  return new Date(y, m - 1, d);
}

function getDaysLeft(dlc: string): number {
  const today = new Date();
  today.setHours(0, 0, 0, 0);
  const expiry = parseDlcDate(dlc);      // heure locale, aucun décalage
  return Math.ceil((expiry.getTime() - today.getTime()) / 86400000);
}

// affichage
parseDlcDate(p.dlc).toLocaleDateString(...)  // cohérent
```

## Impact
- Dates DLC/DLUO correctement affichées pour tous les utilisateurs en UTC+ (France, Maroc, etc.)
- Alertes "expiré" / "bientôt" déclenchées au bon jour calendaire
- Aucune régression (localStorage non modifié, les données existantes sont compatibles)
