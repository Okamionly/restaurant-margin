## Bug sélectionné

**Fichier** : `client/src/components/SmartIngredientInput.tsx` — ligne 172 (avant fix)

**Catégorie** : toast non traduit (string hardcodée sans i18n)

**Avant** :
```ts
setToast('Ingredient ajoute a l\'inventaire');
```

**Après** :
```ts
setToast(t('ingredients.ingredientCreated'));
```

## Détail du fix

1. Ajout de l'import `useTranslation` depuis `../hooks/useTranslation`
2. Instanciation `const { t } = useTranslation();` dans le composant
3. Remplacement de la string hardcodée par la clé i18n `ingredients.ingredientCreated`

**Clé disponible dans les 5 locales** :
- `fr` → "Ingrédient ajouté avec succès"
- `en` → "Ingredient added successfully"
- `es` → "Ingrediente agregado con exito"
- `de` → "Zutat erfolgreich hinzugefuegt"
- `ar` → "تم إضافة المكون بنجاح"

## Raison

Le composant `SmartIngredientInput` est utilisé dans plusieurs pages (Recipes, Ingredients, etc.). Le toast affiché lors de la création d'un ingrédient ignorait le système i18n : texte sans accents, non localisable. La clé `ingredients.ingredientCreated` existait déjà dans les 5 fichiers de locale — il manquait uniquement l'appel au hook.
