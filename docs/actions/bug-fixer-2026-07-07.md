## Bug sélectionné
**UX — Suppression sans confirmation dans DlcTracker**

### Fichier
`client/src/pages/DlcTracker.tsx` — ligne 129

### Constat
La fonction `handleDelete` supprimait instantanément un produit DLC au clic sur la corbeille, sans demander confirmation. Toutes les autres pages du codebase utilisent `window.confirm` avant une suppression destructive (Clients.tsx, InvoiceScanner.tsx, Comptabilite.tsx, KitchenMode.tsx, EmailMarketing.tsx, Devis.tsx, AIAssistant.tsx).

### Avant
```typescript
function handleDelete(id: string) {
  const updated = products.filter((p: DlcProduct) => p.id !== id);
  setProducts(updated);
  saveProducts(updated);
}
```

### Après
```typescript
function handleDelete(id: string) {
  const product = products.find((p: DlcProduct) => p.id === id);
  if (!window.confirm(`Supprimer "${product?.name}" ?`)) return;
  const updated = products.filter((p: DlcProduct) => p.id !== id);
  setProducts(updated);
  saveProducts(updated);
}
```

### Raison
Cohérence UX avec le reste du codebase. Prévient les suppressions accidentelles sur mobile (tap involontaire).
