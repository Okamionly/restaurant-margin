## Bug sélectionné

**`alert()` natif + catch silencieux sur les actions photo dans RecipeDetail**

`handlePhotoUpload` utilisait `alert('Image trop lourde (max 5 Mo)')` — dialogue bloquant natif du navigateur, incohérent avec le design system W&B. De plus, les blocs `catch` de `handlePhotoUpload` et `handleDeletePhoto` faisaient uniquement `console.error`, sans aucun feedback visible à l'utilisateur. En cas d'erreur réseau ou serveur, la page restait muette.

---

## Fix appliqué

**Fichier** : `client/src/pages/RecipeDetail.tsx`

### 1. Ajout du state (ligne 139)
```ts
// Avant : pas de state photo error
// Après :
const [photoError, setPhotoError] = useState<string | null>(null);
```

### 2. handlePhotoUpload — validation taille (ligne 214)
```ts
// Avant :
if (file.size > 5 * 1024 * 1024) { alert('Image trop lourde (max 5 Mo)'); return; }

// Après :
if (file.size > 5 * 1024 * 1024) { setPhotoError('Image trop lourde (max 5 Mo)'); return; }
```

### 3. handlePhotoUpload — catch (ligne 228)
```ts
// Avant :
} catch (err) { console.error('Erreur upload photo', err); }

// Après :
} catch (err) { setPhotoError('Erreur lors de l\'upload de la photo'); }
```

### 4. handleDeletePhoto — catch (ligne 238)
```ts
// Avant :
} catch (err) { console.error('Erreur suppression photo', err); }

// Après :
} catch (err) { setPhotoError('Erreur lors de la suppression de la photo'); }
```

### 5. Toast JSX ajouté (ligne 1825) — cohérent avec le pattern optimizeError existant
```tsx
{photoError && (
  <div className="fixed bottom-16 right-4 z-50 bg-red-600 text-white px-4 py-3 rounded-xl shadow-lg flex items-center gap-3 animate-fade-in no-print">
    <AlertTriangle className="w-5 h-5 flex-shrink-0" />
    <span className="text-sm">{photoError}</span>
    <button onClick={() => setPhotoError(null)} className="p-1 hover:bg-red-500 rounded-lg transition-colors">
      <X className="w-4 h-4" />
    </button>
  </div>
)}
```

Positionné à `bottom-16` pour ne pas chevaucher le toast `optimizeError` (à `bottom-4`).

---

## Raison

`alert()` est bloquant et cassé sur mobile (Samsung Tab A9+). Les catch silencieux laissaient l'utilisateur sans feedback en cas d'erreur réseau — l'action semblait ne rien faire. Fix aligné sur le pattern toast déjà en place dans la même page (`optimizeError`).
