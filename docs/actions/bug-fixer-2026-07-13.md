## Fix du jour

**Fichier** : `api-lib/prisma.ts`  
**Type** : Amélioration monitoring (réponse à recommandation CTO)

### Avant
```ts
export const prisma =
  globalForPrisma.prisma ??
  new PrismaClient({
    log: process.env.NODE_ENV === 'production' ? ['error'] : ['error', 'warn'],
  });
```
Aucune visibilité sur les requêtes Prisma lentes. Les queries à 200-999ms passaient silencieusement.

### Après
```ts
function createPrismaClient(): PrismaClient {
  const client = new PrismaClient({
    log: [
      { emit: 'event', level: 'query' },
      { emit: 'stdout', level: 'error' },
      ...(process.env.NODE_ENV !== 'production' ? [{ emit: 'stdout' as const, level: 'warn' as const }] : []),
    ],
  });

  // Log queries slower than 200ms — helps identify Prisma/Supabase bottlenecks.
  client.$on('query', (e: Prisma.QueryEvent) => {
    if (e.duration >= 200) {
      console.warn(`SLOW_QUERY ${e.duration}ms | ${e.query.slice(0, 120)}`);
    }
  });

  return client;
}
```
Chaque requête Prisma >= 200ms produit un log `SLOW_QUERY` avec durée et début de la query. Permet d'identifier les goulots côté BDD (Supabase Free, ~60 connexions max).

### Raison
CTO report 2026-07-12 signale responseTime API à 851ms (seuil d'alerte 1200ms) et recommande explicitement : *"Ajouter un log de slow queries (>200ms) dans l'API"*. Fix préventif avant dépassement du seuil.
