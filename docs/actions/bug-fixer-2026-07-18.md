# Bug Fixer — 2026-07-18

## Bug fixé : Signature svix non vérifiée sur /api/inbound/email

**Source** : TODO signalé par CTO dans docs/reports/cto-last.md (dette technique #2)  
**Fichier** : `api/index.ts`  
**Commit** : `fix: verifier signature svix sur webhook Resend /api/inbound/email`

---

## Problème

L'endpoint `/api/inbound/email` (webhook Resend `email.received`) n'effectuait aucune vérification de signature. N'importe quel acteur externe pouvait envoyer de faux événements Resend pour injecter des messages dans la messagerie.

**CWE-345** : Insufficient Verification of Data Authenticity.

---

## Solution

### 1. Capture du body brut (api/index.ts ~ligne 187)

Ajout de l'option `verify` sur `express.json()` pour stocker le body brut dans `req.rawBody` uniquement pour `/api/inbound/email` (overhead nul sur les autres routes) :

```typescript
// Avant
app.use(express.json({ limit: '10mb' }));

// Après
app.use(express.json({
  limit: '10mb',
  verify: (req: any, _res, buf) => {
    if (req.url === '/api/inbound/email') {
      req.rawBody = buf.toString();
    }
  },
}));
```

### 2. Fonction verifyResendSignature() (api/index.ts ~ligne 2797)

Ajout d'une fonction de vérification HMAC-SHA256 utilisant le module `crypto` (déjà importé) — pas de nouvelle dépendance :

- Vérifie la présence des headers `svix-id`, `svix-timestamp`, `svix-signature`
- Protection replay : timestamp max 5 minutes
- Signature : `HMAC-SHA256(svix-id.svix-timestamp.rawBody, whsec_key)`
- Comparaison `timingSafeEqual` (anti timing attack)
- Graceful degradation : si `RESEND_WEBHOOK_SECRET` absent, toutes les requêtes passent (backward-compat)
