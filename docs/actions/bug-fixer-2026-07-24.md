# Bug Fixer — 2026-07-24

## Source du bug

Détecté via grep des toasts dans le code source. Le CTO et le QA ne signalent aucun bug fonctionnel (0 erreurs TS, 0 TODO/FIXME). Bug choisi : toasts i18n manquants dans `MenuCalendar.tsx`.

## Fichier concerné

`client/src/pages/MenuCalendar.tsx`

## Problème

La page `MenuCalendar` n'importait pas `useTranslation` du tout. 6 messages toast étaient hardcodés en français, cassant l'internationalisation pour les utilisateurs en langue étrangère.

## Avant

```tsx
// Pas d'import useTranslation
showToast(`${recipe.name} ajouté au ${formatDateKey(date)}`, 'success');
showToast('Erreur lors de l\'ajout', 'error');
showToast('Erreur lors de la suppression', 'error');
showToast(`${dragEntry.recipe.name} déplacé au ${targetKey}`, 'success');
showToast('Erreur lors du déplacement', 'error');
showToast('Liste de courses exportée', 'success');
```

## Après

```tsx
import { useTranslation } from '../hooks/useTranslation';
// const { t } = useTranslation(); dans le composant

showToast(`${recipe.name} ${t('menuCalendar.addedTo')} ${formatDateKey(date)}`, 'success');
showToast(t('menuCalendar.errorAdding'), 'error');
showToast(t('menuCalendar.errorDeleting'), 'error');
showToast(`${dragEntry.recipe.name} ${t('menuCalendar.movedTo')} ${targetKey}`, 'success');
showToast(t('menuCalendar.errorMoving'), 'error');
showToast(t('menuCalendar.shoppingListExported'), 'success');
```

## Clés ajoutées

Section `menuCalendar` ajoutée dans les 5 locales : `fr.json`, `en.json`, `es.json`, `de.json`, `ar.json`.

Clés : `errorAdding`, `errorDeleting`, `errorMoving`, `shoppingListExported`, `addedTo`, `movedTo`.

## Raison

Cohérence i18n : toutes les autres pages utilisent `useTranslation`. MenuCalendar était la seule à avoir des toasts 100% hardcodés en français, bloquant les utilisateurs non-francophones.

## Commit

`fix: i18n des toasts hardcodés dans MenuCalendar`
