## Bug détecté

**Type** : UX / affichage incorrect  
**Sévérité** : Moyen — tous les utilisateurs français (UTC+1/+2) affectés  
**Cause racine** : `new Date('YYYY-MM-DD')` parse la chaîne ISO en **minuit UTC**. Quand `toLocaleDateString('fr-FR')` traduit ensuite en heure locale (Paris = UTC+1 ou UTC+2), la date bascule au **jour précédent**.

**Exemple** : le digest du 26 juillet s'affichait "samedi 25 juillet" dans l'interface.

---

## Fichiers modifiés

### 1. `client/src/pages/Actualites.tsx`

**Ligne 622** — En-tête de section Digest :
```diff
- {new Date(digest.digest_date).toLocaleDateString('fr-FR', { weekday: 'long', day: 'numeric', month: 'long' })}
+ {new Date(digest.digest_date + 'T12:00:00').toLocaleDateString('fr-FR', { weekday: 'long', day: 'numeric', month: 'long' })}
```

**Ligne 645** — Options du sélecteur d'archive :

```diff
+ const weekDate = new Date(pub.week_date + 'T12:00:00').toLocaleDateString('fr-FR', { day: 'numeric', month: 'long', year: 'numeric' });
```

---

## Technique du fix

Ajouter `'T12:00:00'` à la chaîne ISO date-only ancre le parsing à **midi heure locale** (pas UTC), ce qui garantit que `toLocaleDateString` produit le bon jour quelle que soit la timezone de l'utilisateur (UTC-11 à UTC+14).
