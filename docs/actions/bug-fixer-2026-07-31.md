## Bug identifié

**Type** : UX / i18n — toasts hardcodés en français sans passer par le système de traduction  
**Fichier** : `client/src/hooks/useUndoDelete.ts`  
**Lignes concernées** : 45, 57, 68, 70 (avant fix)

### Description
Le hook `useUndoDelete` affichait 5 chaînes de texte hardcodées en français directement dans les toasts, contournant complètement le système i18n. Pour un site multi-langue (FR/EN/ES/DE/AR), ces messages restaient en français quelle que soit la langue choisie par l'utilisateur.

### Avant

```ts
showToast('Erreur lors de la suppression', 'error');
// ...
const label = itemLabel ? `"${itemLabel}" supprime` : 'Element supprime';
showToast(label, 'success', { action: { label: 'Annuler', ... } });
// ...
showToast('Restaure avec succes', 'info');
// ...
showToast('Erreur lors de la restauration', 'error');
```

### Après

```ts
showToast(t('common.deleteError'), 'error');
// ...
const label = itemLabel
  ? `"${itemLabel}" ${t('common.itemDeleted')}`
  : t('common.elementDeleted');
showToast(label, 'success', { action: { label: t('common.cancel'), ... } });
// ...
showToast(t('common.restoreSuccess'), 'info');
// ...
showToast(t('common.restoreError'), 'error');
```

## Clés i18n ajoutées

**`client/src/locales/fr.json`** et **`client/src/locales/en.json`** — section `common` :

| Clé | FR | EN |
|-----|----|----|
| `common.deleteError` | Erreur lors de la suppression | Error deleting item |
| `common.elementDeleted` | Élément supprimé | Item deleted |
| `common.itemDeleted` | supprimé | deleted |
| `common.restoreSuccess` | Restauré avec succès | Restored successfully |
| `common.restoreError` | Erreur lors de la restauration | Error restoring item |

Note : `common.cancel` (Annuler) existait déjà, réutilisé pour le bouton d'action du toast.

## Impact
- Les toasts de suppression/restauration sont désormais traduits pour FR et EN
- ES/DE/AR tombent en fallback FR (comportement attendu, pas de section `common` dans ces locales)
- Aucun changement de comportement fonctionnel
