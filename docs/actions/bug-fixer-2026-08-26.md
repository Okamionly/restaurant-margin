## Bug sélectionné : locale reset à 'fr' à chaque reload

**Fichier** : `client/src/hooks/useTranslation.ts` — ligne 52

**Symptôme** : L'utilisateur sélectionne une langue (ex : English, Deutsch) dans Settings → `setLocale('en')` est appelé → la page affiche immédiatement l'anglais. Mais au prochain reload, la langue revenait systématiquement au français.

**Cause** : Le `useState` initializer lisait bien localStorage mais retournait `'fr'` dans les deux branches de la condition :

```typescript
// AVANT (cassé)
return stored === 'fr' ? 'fr' : 'fr';
```

**Fix** :

```typescript
// APRÈS (corrigé)
return (stored && localeLoaders[stored]) ? stored : 'fr';
```

La condition vérifie que la locale stockée correspond bien à un chargeur valide (fr fallback intégré, en/de/es/ar via localeLoaders). Si la valeur est invalide ou absente, on retombe sur 'fr'.

## Impact

- Language switcher dans Settings (Settings.tsx:919) désormais fonctionnel et persistant entre sessions.
- Aucun impact sur les utilisateurs en 'fr' (chemin par défaut inchangé).
- Locales DE/ES/AR : les traductions disponibles (~448 clés sur 1649) s'affichent correctement ; les clés manquantes fallback sur FR comme prévu.
