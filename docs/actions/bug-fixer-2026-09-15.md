## Bug fixé : tiret résiduel dans les slugs multi-mots de NicheLanding

### Fichier
`client/src/pages/NicheLanding.tsx` — 2 occurrences

### Symptôme
`.replace('-', ' ')` en JavaScript ne remplace que la **première** occurrence d'un tiret. Les slugs avec deux tirets (`cafe-coffee-shop`, `kebab-fast-food`) affichaient un tiret résiduel dans :
- Le CTA final : "Ne perdez plus de marge sur votre cafe coffee**-**shop"
- Les cross-links : "cafe coffee**-**shop", "kebab fast**-**food"

### Lignes concernées

**Avant** (×2) :
```tsx
// ligne 1021
{config.slug.replace('-', ' ')}

// ligne 1046
{n.slug.replace('-', ' ')}
```

**Après** (×2) :
```tsx
// ligne 1021
{config.slug.replace(/-/g, ' ')}

// ligne 1046
{n.slug.replace(/-/g, ' ')}
```

### Slugs affectés
- `cafe-coffee-shop` → "cafe coffee shop" ✓ (était "cafe coffee-shop")
- `kebab-fast-food` → "kebab fast food" ✓ (était "kebab fast-food")

### Raison
Regex globale `/-/g` remplace toutes les occurrences, contrairement à la string littérale `'-'` qui s'arrête après le premier match. Bug introduit lors de la création du composant NicheLanding.
