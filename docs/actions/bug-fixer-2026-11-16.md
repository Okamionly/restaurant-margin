## Bug choisi

**Fichier** : `api/index.ts`, lignes 564–629  
**Symptôme** : Le endpoint `/api/health?deep=1` répond en ~1 400 ms (CTO-2026-11-15 : seuil cible 800 ms). La sonde DB et la sonde IA s'exécutaient **séquentiellement** : `await verifierBase()` PUIS `await anthropic.messages.create(...)`.

---

## Correction

**Avant** : deux `await` séquentiels (db → ia), soit `time_db + time_ia ≈ 1 400 ms`.  
**Après** : `Promise.all([verifierBase(), aiProbe])` — les deux probes s'exécutent en parallèle, latence attendue `max(time_db, time_ia) ≈ 700 ms`.

La logique de cache (`aiProbeCache`, `dbHealthCache`) est entièrement préservée :
- Hit de cache IA → `Promise.resolve({ status, detail })` sans appel réseau
- Miss de cache → appel API parallèle au SELECT 1 DB
- Premier boot (`cachedAt === 0`) → DB vérifiée en parallèle avec l'IA
