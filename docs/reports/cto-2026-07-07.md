## Dette technique — TOP 3

1. **api/index.ts monolithique (6 443 lignes)** — Fichier critique. Toute la logique métier, routes, middleware et config dans un seul fichier. Risque de conflits de merge élevé, impossible à maintenir seul à terme. Priorité haute : découper en modules par domaine (auth, recipes, ingredients, ai, mercuriale).

2. **163 pages React sans lazy-loading systématique** — Bundle initial probablement trop lourd. Vérifier que toutes les pages passent par `lazy()` dans App.tsx. Un audit du bundle size (vite build --analyze) permettrait de cibler les quick wins.

3. **ResponseTime API à 943ms** — Seuil acceptable mais à surveiller. Pas de cache visible côté API. Si le load augmente avec l'acquisition, il faudra introduire du cache Redis sur les endpoints les plus sollicités (recettes, ingrédients, suggestions IA).

## Refacto prioritaire

- **Éclater api/index.ts** : créer `api/routes/`, `api/controllers/`, `api/middleware/` — chaque agent peut travailler en parallèle sans conflit
- **Bundle audit** : lancer `npx vite build --mode analyze` et identifier les pages qui gonflent le bundle
- **Response time** : ajouter `Cache-Control` sur les GET publics (outils SEO, blog) pour décharger le serveur
