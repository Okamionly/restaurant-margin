## Dette technique — TOP 3

1. **api/index.ts monolithique (6 626 LOC)** — fichier unique de 6 600 lignes impossible à maintenir à terme. Refactoring prioritaire : découper en routeurs modulaires par domaine (`/auth`, `/recipes`, `/ai`, `/mercuriale`, etc.). Risque : tout bug ou merge conflict sur ce fichier bloque tout le backend.

2. **Response time prod à 996ms** — quasi 1 seconde de latence API. Cause probable : cold start Render/Railway ou requête DB sans index sur des tables grandissantes. À investiguer : `EXPLAIN ANALYZE` sur les endpoints `/api/recipes` et `/api/ingredients`. Seuil acceptable : < 400ms.

3. **0 nouveaux utilisateurs en 24h** — signal d'acquisition faible. Pas une dette technique mais indicateur de priorité produit. Conversion tunnel à auditer : landing → signup → onboarding.

## Refacto prioritaire

- **Court terme :** Extraire les routes `ai.ts`, `mercuriale.ts`, `auth.ts` hors de `api/index.ts` → gain de lisibilité immédiat, facilite les code reviews
- **Moyen terme :** Ajouter monitoring response time (ex: Sentry Performance ou simple middleware Express) pour détecter les régressions latence avant les utilisateurs
- **Optionnel :** Audit index PostgreSQL sur les colonnes filtrées fréquemment (`user_id`, `created_at`, `recipe_id`)

## Résumé
Infra stable, zéro erreur TypeScript, zéro dette TODO/FIXME. Le point d'attention technique principal reste la concentration excessive de code dans `api/index.ts`. La latence à ~1s mérite une investigation ciblée cette semaine.
