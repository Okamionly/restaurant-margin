## Dette technique — Top 3

### 1. 🔴 api/index.ts — Monolithe critique (7 817 lignes)
Toute la logique backend est concentrée dans un seul fichier. C'est le point de défaillance le plus risqué : lisibilité nulle, conflits de merge fréquents entre agents, impossible à tester unitairement.

**Refacto prioritaire** : extraire par domaine vers `api/routes/` (déjà partiellement fait pour auth, ai, mercuriale). Les blocs suivants doivent devenir des fichiers séparés : recettes, ingrédients, fournisseurs, planning, HACCP, commandes auto, analytics.

### 2. 🟠 Pages géantes non découpées
Trois pages dépassent 3 000 lignes :
- `Recipes.tsx` — 4 497 LOC
- `Suppliers.tsx` — 3 767 LOC
- `Clients.tsx` — 3 348 LOC

Ces fichiers mélangent UI, logique métier et appels API. Ils doivent être découpés en sous-composants et hooks spécialisés.

### 3. 🟡 Latence API health élevée (1 483 ms)
Le endpoint `/api/health?deep=1` met 1,5 s à répondre, probablement dû au cold start Supabase. Acceptable pour un healthcheck deep, mais à surveiller : si la latence monte côté utilisateur réel, ce sera détectable ici en premier.
