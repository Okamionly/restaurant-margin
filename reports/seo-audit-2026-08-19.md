## 2. Analyse concurrent : Restopilot

Page analysée : `restopilot.ai/blog/coefficient-multiplicateur-restauration/`
(place 5 sur la requête où RestauMargin est absent).

| Critère | Restopilot | RestauMargin (`/blog/coefficient-multiplicateur`) |
|---|---|---|
| Mots | ~5 500 | 4 915 |
| H2 thématiques | 10 | ~22 (via composant `SectionHeading`) |
| FAQ | 5 questions | 18 entrées |
| Tableaux de référence | 2 | plusieurs (12 catégories, méga-tableau) |
| Schema JSON-LD | **aucun** | FAQPage + BreadcrumbList + Article |
| Maillage interne | oui | fort (19 liens internes) |
| **Contenu dans le HTML servi** | **oui** | **non** |

**Lecture** : sur tous les critères classiques, RestauMargin est égal ou supérieur —
et Restopilot ranke **sans aucun schema markup**. Le schema n'est donc pas le
levier. La seule variable qui sépare les deux pages est la dernière ligne.

**Preuve A/B** : le même outil (WebFetch) a extrait de Restopilot ses 5 500 mots
et ses 10 H2 ; il n'a extrait de RestauMargin qu'un titre, un fil d'ariane, un
sommaire et « Chargement de l'application interactive… ».

## 3. Cause racine — mesurée en production

`GET /blog/coefficient-multiplicateur` renvoyait :

- le bon `<title>` ✅
- la bonne `<meta description>` ✅
- fil d'ariane + sommaire générique + liens connexes
- puis **« Chargement de l'application interactive… »**
- **zéro mot du corps de l'article**

Les 4 915 mots n'existent que dans le bundle React.

`client/scripts/prerender.cjs` (977 lignes) ne fait que du `String.replace` sur
`index.html` — **aucun moteur de rendu** (ni puppeteer, ni `renderToString`).
C'est un injecteur de meta, pas un prerender de contenu.

Pire : le corps injecté est un **gabarit par catégorie, identique pour les 51
articles** — une phrase type avec le mot-clé substitué, puis un sommaire de 6
puces strictement commun (« Définitions et formules essentielles à connaître »,
« Méthode de calcul pas à pas »…). Le commentaire du code dit viser à éviter le
duplicate content ; l'implémentation produit 51 pages quasi jumelles.

**Conséquence, et elle explique tout le clivage du §1** : les requêtes de marque
et commerciales rankent (title + meta + autorité suffisent), les requêtes
informationnelles ne *peuvent pas* ranker — il n'y a aucun texte à indexer.

> À noter : `vercel.json` surcharge le build (`vite build && node scripts/prerender.cjs`),
> donc le prerender tourne bien en CI. Le défaut est dans son contenu, pas dans son exécution.

## 4. Améliorations

### ✅ Appliquée — le prerender sert le vrai contenu
Commit `65168ab`.

1. `prerender.cjs` accepte un champ optionnel **`seoBody`** par route, prioritaire
   sur le gabarit de catégorie. Les routes sans `seoBody` gardent **exactement**
   leur comportement (vérifié sur `prime-cost-restaurant`).
2. `/blog/coefficient-multiplicateur` reçoit son contenu réel : 5 H2 thématiques,
   tableau des 12 catégories, 2 cas chiffrés, erreurs fréquentes.

Vérification sur le HTML réellement généré :

| | avant | après |
|---|---|---|
| H2 servis | 2 (dont 1 générique) | **6 (5 thématiques)** |
| Gabarit générique | présent | **absent** |
| Poids | 17,7 Ko | **24,3 Ko** |

Chiffres repris de l'article et recontrôlés : pizza 10,90 TTC ÷ 1,10 = 9,91 HT ;
9,91 ÷ 1,58 = **x6,27** ; marge 8,33 € ; food cost 15,9 %. Aucun chiffre inventé.

### ⏳ À faire — étendre aux autres pages informationnelles
Les ~50 autres articles servent toujours le gabarit. Deux voies :
- **court terme** : `seoBody` sur les pages des requêtes qui échouent
  (food cost, prime cost, menu engineering, marge brute, prix de vente plat, rentabilité) ;
- **structurel** : vrai prerender headless. `@playwright/test` est déjà en devDep,
  mais il faudrait installer un binaire navigateur dans le build Vercel
  (minutes de build + risque sur les 145 URLs). **À arbitrer par le propriétaire** —
  je ne l'ai pas engagé seul depuis une tâche planifiée.

### ⏳ À vérifier — incohérence de chiffre visible en SERP
La `meta description` annonce « pizzeria **3.0** ». Or la page elle-même donne
« Pizzas / Burgers **x 4,0 à 6,0** » et son cas chiffré pizzeria ressort à **x6,27**.
S'il s'agit d'un coefficient d'établissement (et non de plat), il faut le dire ;
sinon c'est une contradiction affichée dans l'extrait Google. À trancher par le propriétaire.

## 5. Blocages rencontrés

| Blocage | Détail | Qui peut débloquer |
|---|---|---|
| **Vercel MCP** | `list_deployments` → **403 Forbidden** | propriétaire (permissions du connecteur) |
| **IndexNow / Bing** | **403 `UserForbiddedToAccessSite`** sur `api.indexnow.org` **et** `bing.com`. Yandex accepte (202). | propriétaire |
| Positions google.fr | outil de recherche géolocalisé US | — |

**Important sur le 403 IndexNow** : le brief dit « 403 = le fichier clé n'est pas
servi ». **Ce n'est pas le cas ici** — vérifié en direct :
`GET /2705a97b…951.txt` → **HTTP 200, `text/plain`, 64 octets, contenu exact**.
Le motif est donc la **propriété du site non vérifiée dans Bing Webmaster Tools**
(cohérent avec la note mémoire « Bing WMT à claim »). Le canal que le brief
qualifie de prioritaire est **hors service tant que le site n'est pas claim**.
