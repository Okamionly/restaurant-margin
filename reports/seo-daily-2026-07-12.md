## 🔎 Bug SEO trouvé + corrigé (bonus du jour)
En vérifiant le rendu live, découverte que le **schema JSON-LD `Article` n'était émis sur AUCUNE page blog**. Cause : `SEOHead` passait plusieurs `<script type="application/ld+json">` frères via `.map()`, et **react-helmet-async en dropait silencieusement une partie** — sur les pages blog, seul `BreadcrumbList` sortait des schemas de page ; l'`Article` (datePublished/dateModified/author) n'atteignait jamais le DOM (confirmé sur le site prod déployé).

**Fix** (`client/src/components/SEOHead.tsx`, commit `502787f`) : combiner tous les schemas de page en **un seul script `@graph`** (pattern recommandé par Google, rendu fiable). Pages à schema unique inchangées. → restaure l'`Article` structured data sur **toutes** les pages blog (~40 pages), gros signal E-E-A-T + freshness (dateModified) pour Google.

Note vérif : impossible de confirmer en local (le **service worker PWA** sert un shell caché périmé → helmet paraît inerte sur localhost). Vérification autoritative = sur le déploiement prod (assets frais) post-deploy + Google Rich Results Test.
