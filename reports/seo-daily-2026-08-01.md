## 1. Le défaut : un hôte tiers sur le chemin du texte, sans preconnect

Les polices du site sont servies par Fontshare, en **deux origines distinctes** :

- `api.fontshare.com` sert le **CSS**
- `cdn.fontshare.com` sert les **fichiers `.woff2`** — vérifié en lisant le CSS réel :

```
url('//cdn.fontshare.com/wf/TTX2Z3BF.../....woff2')
```

Le second hôte n'est donc **découvert qu'après le parse du CSS**. Sans preconnect, un cycle DNS + TCP + TLS complet s'insère **en série** sur le chemin de rendu du texte. Or ces polices ne sont pas décoratives :

```
src/index.css:16 → font-family: 'General Sans', ...   (corps de tout le site)
tailwind.config  → satoshi: ['Satoshi', ...]          (titres, donc les H1)
```

## 2. Trois corrections (`57ca49d`)

**a. `preconnect` ajouté vers `cdn.fontshare.com`** — l'hôte qui sert réellement les polices.

**b. Le `crossorigin` était sur le mauvais hôte.** Une connexion préchauffée en mode **CORS anonyme n'est pas réutilisable** par une requête non-CORS, et inversement. `api.fontshare.com` sert un CSS (non-CORS) et portait pourtant `crossorigin` → sa connexion préchauffée ne pouvait pas servir. Corrigé selon le pattern canonique Google Fonts :

```html
<link rel="preconnect" href="https://api.fontshare.com" />            <!-- CSS : sans -->
<link rel="preconnect" href="https://cdn.fontshare.com" crossorigin /> <!-- woff2 : avec -->
```

**c. Deux hints morts retirés** :
- `supabase.co` (preconnect **et** dns-prefetch) → **0 requête** mesurée. Le front n'appelle jamais Supabase (c'est le backend qui s'en charge ; l'unique occurrence dans `client/src` est un libellé de coût dans `AdminFinance.tsx`). L'origine était **fausse** de surcroît : un projet Supabase vit sur `<ref>.supabase.co`, et un preconnect ne vaut que pour une origine **exacte**. Un preconnect inutilisé consomme un slot de connexion sur le chemin critique.
- `sentry.io` → 0 requête ; le vrai hôte est `browser.sentry-cdn.com`, qui conserve son dns-prefetch.

**d. Bloc polices remonté en haut du `<head>`** — il était ligne ~198, après Google Analytics et tout le JSON-LD. Le navigateur n'ouvre la connexion qu'en parsant la balise : plus bas = plus tard.

### ⚠️ Ce que je n'ai PAS mesuré — et pourquoi

**Aucun gain en millisecondes n'est avancé ici.** Fontshare n'envoie pas d'en-tête `Timing-Allow-Origin` : pour ces ressources cross-origin, `domainLookupStart/End` et `connectStart/End` sont **forcés à 0** dans l'API Resource Timing. Le coût DNS+TLS supprimé est donc **structurellement réel mais non chiffrable depuis ce poste**.

Ce qui est prouvé : l'existence de la chaîne (le CSS pointe vers un second hôte), le fait que cet hôte était contacté 3 fois sans preconnect, et que le hint est désormais servi sur les 116 pages. Le gain lui-même repose sur le comportement documenté de la plateforme, pas sur une mesure locale.

> **Note de méthode** : la première tentative de mesure a renvoyé « aucune police chargée » — le CSS venait du **cache disque**. Le second passage a nécessité de désenregistrer le Service Worker et de vider les caches. C'est exactement le piège qui avait produit un faux verdict le 27/07. Le contrôle du cache fait partie du protocole, pas de la conclusion.
