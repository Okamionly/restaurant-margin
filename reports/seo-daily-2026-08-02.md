### ⚠️ Artefact de vérification à ne pas confondre avec un bug

Dans le navigateur, `document.title` et le canonical affichaient **les valeurs de la homepage** sur toutes les pages blog. Ce n'est **pas** un défaut de production :

- `navigator.serviceWorker.controller` = `https://www.restaumargin.fr/sw.js` → **le Service Worker PWA sert le shell racine** sur les navigations (navigation fallback Workbox).
- Le même contenu récupéré par `fetch(url, {cache:'reload'})` — qui contourne ce fallback — renvoie **le bon title pour chaque page**, et `curl` en UA Googlebot confirme les canonicals corrects.
- Googlebot n'utilise pas de Service Worker → il reçoit le HTML prerendu réel.

C'est exactement le piège documenté le 12/07. **Conséquence utile** : `document.querySelectorAll('[data-rh]').length` vaut **0** en navigateur — react-helmet-async n'applique aucune balise côté client. Le SEO du site repose donc **intégralement** sur le prerender, ce qui rend une omission dans `prerender.cjs` non pas « dégradante » mais **fatale** pour la page concernée. Le garde-fou posé aujourd'hui protège le seul mécanisme qui porte réellement les balises.

*(Capture d'écran impossible sur ce run planifié : le panneau navigateur n'est pas affiché, donc la page ne compose pas d'image. Vérification faite au niveau du DOM rendu, ce qui est plus probant ici : géométrie du bloc, attributs `datetime`/`itemProp`, texte réel.)*
