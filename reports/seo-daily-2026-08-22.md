## Optimisation identifiée et appliquée

**Preload direct de la police LCP (`Satoshi 900` woff2).**

Landing, Pricing et les titres d'article blog utilisent tous `font-extrabold`
(Tailwind = graisse 800) sur Satoshi, qui n'a que les graisses 400/500/700/900
chargées → l'algorithme de matching CSS Fonts résout vers **900** (la plus proche
au-dessus). Cette police est donc celle du **texte LCP** (H1) sur les 3 pages
ciblées — mais son URL n'était découverte qu'après un aller-retour complet :
`HTML → <link preload as=style> → fetch CSS Fontshare → parse @font-face → fetch woff2`.

Fix : `<link rel="preload" as="font" type="font/woff2" crossorigin>` pointant
directement sur le fichier woff2 (résolu via l'API CSS Fontshare, vérifié
`HTTP 200`, `content-type: font/woff2`, `Access-Control-Allow-Origin: *` — donc
pas de double-fetch malgré le `crossorigin`). Le fetch du woff2 démarre
maintenant en parallèle du CSS dès le haut du `<head>`, au lieu d'attendre le
parse du CSS.

Risque documenté dans le commentaire du code : l'URL Fontshare contient un hash
de contenu qui peut être régénéré si la police est republiée côté CDN — dans ce
cas le preload est simplement ignoré (aucune régression), à revalider si Satoshi
est un jour mis à jour.
