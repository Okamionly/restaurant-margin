## Ce qui a été fait

- `client/scripts/prerender-ssr.mjs` (nouveau) : lit les routes de `App.tsx`, charge chaque
  page via le SSR de Vite, la rend avec `renderToString` dans `HelmetProvider` + `MemoryRouter`,
  écrit `dist/.ssr/manifest.json`. 90/90 pages en ~7 s. Tolérant par page (repli sur le
  résumé, journalisé) ; échoue seulement si aucune page n'est rendue.
- `client/scripts/prerender.cjs` : injecte le corps rendu à la place du résumé quand il existe,
  contrôle le H1 réel de l'article, supprime `dist/.ssr` (il ne doit pas être servi), et le log
  final dit combien de pages ont reçu un corps complet.
- `vercel.json` : l'étape SSR s'exécute entre `vite build` et `prerender.cjs`. Si elle
  échoue, le déploiement continue avec le résumé, et le log de `prerender.cjs` l'affiche
  (« 0 avec corps complet SSR »).

L'app monte avec `createRoot` (pas d'hydratation) : React remplace le HTML statique au
premier rendu. Le DOM statique et le DOM React sont les mêmes, donc pas de contenu différent
pour les robots (aucun cloaking).

## Mesure perf (Playwright headless, build local, `/blog/calcul-marge-restaurant`)

Conditions : mobile 412×915, CPU ×4, réseau 1,6 Mb/s + 150 ms, serveur HTTP dans le processus
de test avec gzip, ressources externes bloquées, 6 runs par bras, bras alternés (3+3).

| Bras | LCP (6 runs, ms) | FCP médian | CLS |
|---|---|---|---|
| Résumé (avant) | 1340, 1412, 1428, **2348, 2376, 2824** | ~1 420 ms | 0,014 |
| Corps complet (après) | 1620, 1640, 1648, 1696, 1720, 1788 | ~1 670 ms | 0,014 |

- **LCP** : avant, la distribution était bimodale. Dans 3 runs sur 6, le `<p>` rendu par
  React à 2,3-2,8 s devenait le LCP. Après, le LCP tombe sur le contenu statique dans les
  6 runs, et la traîne lente disparaît. Le p75 passe d'environ 2,4 s à environ 1,7 s
  (petit échantillon, à confirmer en production).
- **FCP : environ +250 ms**. C'est un coût réel : le HTML est plus lourd (page la plus
  lourde : 147 Ko bruts, 29,7 Ko en gzip).
- CLS inchangé. Mêmes erreurs console dans les deux bras (ressources externes bloquées par
  le test), aucune nouvelle.
- Contrôlé sans JS : article, niche pizzeria, alternative Zenchef et accueil. Chaque page
  a un H1 unique et un rendu stylé (capture vérifiée).

Piège de mesure rencontré : bloquer les chunks des fonds WebGL (méthode du 26/09) fait
désormais tomber l'ErrorBoundary de l'app (« Failed to fetch dynamically imported
module »). Cette mesure-là a donc été faite **avec** les fonds servis. Autre piège :
`route.fulfill` de Playwright contourne le bridage réseau CDP. La première mesure,
non bridée, inversait le verdict sur le LCP ; elle a été refaite avec un vrai serveur HTTP.
