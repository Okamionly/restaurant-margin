## Action du jour : optimisation technique (rotation samedi)

### Constat : le chunk d'entrée avait regrossi de 55 %
Build local avant intervention : `index-*.js` = **306,9 Ko bruts / 83,0 Ko gzip**, contre 198 Ko le 14/11. Ce fichier est téléchargé et parsé par **chaque** visiteur (articles, `/pricing`, accueil) avant que React prenne la main sur le HTML prérendu.

Attribution des octets par sourcemap (build `--sourcemap` hors dépôt) : environ 108 Ko venaient du dictionnaire `locales/fr.json` (127 Ko de JSON), plus 27 Ko d'icônes lucide.

**Cause** : commit `959297d` du 15/11 (un agent de correction i18n). Il a ajouté `useTranslation()` dans `AppLayout` pour traduire un toast « bientôt disponible ». `AppLayout` vivait dans `App.tsx`, donc dans le chunk d'entrée. Résultat : tout `fr.json` est parti sur le chemin critique de toutes les pages publiques. Le correctif était juste, son effet de bord ne se voyait pas.

### Appliqué
- `AppLayout` (coquille de l'espace connecté), `SidebarRestaurantSelector`, les types de navigation et les 76 déclarations de pages de l'espace connecté passent dans `client/src/AppLayout.tsx`. Le fichier est chargé par `lazyRetry` (le helper du projet pour les chunks périmés), dans un `<Suspense>` dont le repli est le même « Chargement... » que `ProtectedRoute`.
- `lazyRetry` part dans `client/src/utils/lazyRetry.ts`, pour éviter un import circulaire App ↔ AppLayout.
- `App.tsx` passe de 1471 à environ 440 lignes, et ses imports devenus inutiles sont retirés (dont `useTranslation` et 49 icônes).
- `SEGMENTS_APPLICATION` et `RouteApplicationOuIntrouvable` restent dans `App.tsx` : la vraie 404 publique ne dépend pas du nouveau chunk.
